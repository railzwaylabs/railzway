# Security Policy

## Supported Versions

Railzway is an actively developed billing engine. To maintain security while remaining lean, we currently only provide security updates for the **latest stable release** on the `main` branch. 

Users are encouraged to stay up-to-date with the latest version to ensure they have the most recent security patches.

## Reporting a Vulnerability

The Railzway team takes security seriously. If you discover a security vulnerability within this project, please **do not open a public issue**. Instead, please report it privately through one of the following channels:

1. **Email**: Send a detailed report to security@railzway.com (Placeholder - update with your actual security email).
2. **GitHub Private Reporting**: Use the "Report a vulnerability" button in the GitHub Security tab of this repository.

### What to Include in Your Report
To help us triage and fix the issue quickly, please include:
- A descriptive title.
- Steps to reproduce the vulnerability (including a Proof of Concept if possible).
- Potential impact (e.g., "Unauthorized access to ledger data").
- Your contact information for follow-up questions.

## Our Commitment

- **Acknowledgment**: We will acknowledge receipt of your report within 48 hours.
- **Triage**: We will provide a preliminary assessment of the issue within 5 business days.
- **Fix**: We will work to provide a fix as quickly as possible and will keep you informed of the progress.
- **Disclosure**: We follow a policy of coordinated disclosure. We ask that you give us a reasonable amount of time to fix the issue before making any information public.

## Security Practices in Railzway

Railzway is built with financial integrity at its core. For details on our internal security architecture, RBAC models, and audit logging, please refer to our [Security Architecture Documentation](docs/architecture/security.md).

Thank you for helping us keep Railzway secure for everyone.
